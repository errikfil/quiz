# Οδηγός για να συνεχίσεις τον κώδικα

Ξεκίνα με τη διαδρομή ενός παιχνιδιού, όχι διαβάζοντας όλα τα αρχεία με τη σειρά.

## 1. Δημιουργία quiz

`frontend/src/pages/Editor.tsx`: το React state `quiz` περιέχει τίτλο και ερωτήσεις. Το `active` δείχνει ποια ερώτηση επεξεργάζεσαι. Η `updateQuestion` δημιουργεί νέο αντικείμενο αντί να αλλάζει το παλιό state στη θέση του, για να καταλαβαίνει το React ότι χρειάζεται render.

Η `save` ελέγχει όλες τις ερωτήσεις και καλεί το API με Axios. Νέο quiz: POST. Επεξεργασία: PUT μαζί με το owner key στο `X-Quiz-Key` header. Ο server επαναλαμβάνει τον έλεγχο, επειδή ο έλεγχος του browser μπορεί να παρακαμφθεί.

`backend/Models/Quiz.cs`: τα μοντέλα της βάσης, τα input DTOs και οι κανόνες εγκυρότητας. Το `CorrectIndex` είναι αριθμός 0–3, όχι γράμμα. Αν προσθέσεις νέο πεδίο, ενημέρωσε και το TypeScript type στο `frontend/src/types.ts`.

`backend/Program.cs`: σύνθεση των υπηρεσιών, επιλογή provider βάσης, HTTP endpoints. `backend/Data/QuizDbContext.cs`: η σύνδεση των μοντέλων με EF Core.

## 2. Άνοιγμα παιχνιδιού

`frontend/src/pages/Library.tsx`: η `start` ζητά session από τον server. Ο server ελέγχει το owner key, δημιουργεί PIN και ξεχωριστό host token. Το PIN μπορεί να μοιραστεί· το host token όχι.

`backend/Services/LiveRooms.cs`: η `Create` κρατά στιγμιότυπο του quiz. Αν αλλάξεις αργότερα τις ερωτήσεις στη βιβλιοθήκη, το ήδη ανοιχτό παιχνίδι παραμένει σταθερό.

## Έτοιμα θέματα και προσωπικά αντίγραφα

`frontend/src/catalog/quizzes.ts`: ο κοινός θεματικός κατάλογος. Το `categories` ορίζει τις κατηγορίες και το `quizTemplates` τα εννέα quiz με τις ερωτήσεις τους. Η `components/QuizCatalog.tsx` κρατά το επιλεγμένο φίλτρο και εμφανίζει μόνο τα αντίστοιχα πρότυπα.

Η `addTemplate` στη `pages/Library.tsx` στέλνει τίτλο και ερωτήσεις στο υπάρχον POST endpoint. Το νέο quiz αποθηκεύεται κανονικά στη βάση και αποκτά δικό του id και owner key. Το προαιρετικό `templateId` φυλάσσεται μόνο μαζί με την αναφορά της βιβλιοθήκης στον browser, για την ένδειξη κατηγορίας και προσθήκης. Τα παλιότερα quiz δεν χρειάζονται αυτό το πεδίο. Οι αλλαγές στο προσωπικό αντίγραφο δεν μεταβάλλουν τον κατάλογο.

## 3. Ζωντανή επικοινωνία

`backend/Hubs/QuizHub.cs`: η είσοδος των SignalR μηνυμάτων. Η σύνδεση συσχετίζεται με ρόλο και δωμάτιο στο `Context.Items`. Δεν δεχόμαστε ρόλο καθηγητή απλώς επειδή τον έστειλε ο browser. Η λογική του παιχνιδιού βρίσκεται στην υπηρεσία, ώστε το Hub να μένει μικρό.

`frontend/src/useRoom.ts`: δημιουργεί μία SignalR σύνδεση, ακούει το `RoomUpdated` και ενημερώνει το React state. Μετά από reconnect ξανακάνει join, επειδή η νέα σύνδεση έχει νέο connection ID και δεν ανήκει αυτόματα στο παλιό group. Το cleanup κλείνει τη σύνδεση όταν φύγεις από την οθόνη.

## 4. Απάντηση, χρόνος, σκορ

Στη `LiveRooms.Answer` έλεγξε με αυτή τη σειρά: ταυτότητα σύνδεσης, φάση, προθεσμία, αριθμό ερώτησης, επιτρεπτή επιλογή, προηγούμενη απάντηση. Μετά υπολογίζεται το σκορ.

Σωστή απάντηση = `500 + round(500 × remainingSeconds / totalSeconds)`. Λάθος / αναπάντητη = 0. Για να αλλάξεις τον κανόνα, άλλαξε εδώ τον τύπο και ενημέρωσε τις δοκιμές. Δεν χρειάζεται αντίστοιχος υπολογισμός στο frontend.

Το `SemaphoreSlim` αποτρέπει race conditions: για παράδειγμα δύο γρήγορα click δεν πρέπει να προσθέσουν δύο φορές πόντους. Το `RoomClock` κλείνει εκπρόθεσμες ερωτήσεις ακόμη κι όταν δεν στείλει κανείς μήνυμα. Το χρονόμετρο του browser απλώς εμφανίζει την προθεσμία του server, με μια απλή εκτίμηση διαφοράς ρολογιών.

Το `Snapshot` είναι η δημόσια εικόνα του δωματίου. Δεν επιστρέφει tokens και κρύβει τη σωστή απάντηση μέχρι τα αποτελέσματα. Η `VisibleScore` κρύβει επίσης τους νέους πόντους, ώστε να μη συμπεραίνει κάποιος τη σωστή απάντηση κοιτώντας το network traffic.

## 5. Εμφάνιση

- `pages/Home.tsx`: αρχική σελίδα. Η κάρτα προεπισκόπησης είναι διακοσμητικό παράδειγμα, όχι αληθινό δωμάτιο.
- `pages/Join.tsx`: φόρμα PIN και ονόματος.
- `pages/Game.tsx`: lobby, ερώτηση, αποτελέσματα, leaderboard. Το ίδιο component παίρνει ρόλο `host` ή `player`.
- `components/Shared.tsx`: logo, navigation, footer, κουμπί φόρτωσης, λάθη.
- `styles.css`: CSS variables στην αρχή, styles ανά οθόνη και media queries στο τέλος. Το Tailwind χρησιμοποιείται για μικρά utilities και reset· τα επαναλαμβανόμενα στοιχεία έχουν ονομαστικές κλάσεις.

Για προσωπικό χαρακτήρα άλλαξε πρώτα το όνομα, τα χρώματα, το λεξιλόγιο και τα έτοιμα quiz στο `catalog/quizzes.ts`. Κράτα συνεπή τα κείμενα και τους ρόλους. Τα ελληνικά σχόλια εξηγούν αποφάσεις, όχι κάθε αυτονόητη γραμμή.

## Μικρές αλλαγές για εξάσκηση

1. Άλλαξε το χρωματικό θέμα από τις CSS variables και έλεγξε την αντίθεση.
2. Πρόσθεσε ένα quiz στον κατάλογο `catalog/quizzes.ts`: μοναδικό id, κατηγορία, τίτλο, περιγραφή και ερωτήσεις. Το `correctIndex` είναι 0–3.
3. Πρόσθεσε περιγραφή quiz: μοντέλο, DTO, validation, types και editor. Πρώτα οργάνωσε migrations.
4. Πρόσθεσε ιστορικό παιχνιδιών σε νέους πίνακες, ώστε το CSV να μην είναι ο μόνος τρόπος διατήρησης αποτελεσμάτων.
5. Πρόσθεσε accounts με ASP.NET Core Identity και αντικατάστησε την ιδιοκτησία μέσω browser key.

Σε κάθε αλλαγή διατήρησε τον server ως τελική πηγή αλήθειας και τρέξε τους λειτουργικούς ελέγχους. Κατέγραψε στην πτυχιακή τις δικές σου αποφάσεις, δοκιμές και τη βοήθεια εργαλείων σύμφωνα με τον κανονισμό της σχολής σου.
